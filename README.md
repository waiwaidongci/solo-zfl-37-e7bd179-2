# 墨锭试磨室 · 复测排程与盲测复核台

在原「墨锭建档 + 试磨记录」台账之上，扩展出复测批次排程与盲测复核流程。

## 运行

```bash
npm start          # http://localhost:3037
npm run verify     # 端到端主流程验证（自带独立测试数据，不影响正式数据）
```

数据保存在 `data/ink-stick-testing.json`（写库先写临时文件再原子改名，断开/重启后队列、批次、记录保持一致）。

## 角色（页面右上角切换）

- **负责人**：批量创建复测批次（指定优先级、截止时间、检测项、墨锭），按排程开磨。
- **检测人**：对试磨中的批次提交检测结果；提交前看不到任何评分与复核结论（盲测）。
- **复核人**：对待复核批次给出通过/驳回；不能复核自己提交的记录。

## 批次流转

`待排程 → 试磨中 → 待复核 → 已结案`

- 待排程批次由系统按「优先级高 → 截止早 → 创建早」排出当前顺序，页面展示各状态数量、逾期批次与队列。
- 同一墨锭不能同时出现在两个未结案批次（串行与并发占用都只成功一次）。
- 本轮全部墨锭提交齐全后自动转待复核；复核通过结案，驳回则退回试磨中并安排下一轮补充复测。
- 非法跳转、重复提交（同轮同锭唯一 + 幂等键重发）均被拒绝。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/batches` | 批次列表（按身份做盲测脱敏）、队列与统计 |
| POST | `/api/batches` | 负责人建批次（title/itemCodes/priority/deadline/testItems/requestId） |
| POST | `/api/batches/:id/start` | 待排程 → 试磨中 |
| POST | `/api/batches/:id/records` | 检测人提交结果（同锭同轮唯一，齐全自动送复核） |
| POST | `/api/batches/:id/review` | 复核人通过/驳回（自审禁止，驳回必填意见） |
| GET | `/api/items` 等 | 原台账接口保留不变 |

页面为响应式布局，桌面与手机均可操作。
